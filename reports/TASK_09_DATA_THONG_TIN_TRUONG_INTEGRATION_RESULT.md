Targeted TASK 09 tests, full regression, processed-data rebuild, Chroma rebuild,

## Task

Integrate the provided RAW PDF
`data/raw/thong_tin_truong/thong_tin_truong_dhv_2026.pdf` into the 2026
knowledge base, route general school-information questions safely, preserve the
boundary with specialized admissions sources, and verify the rebuilt index.

## Baseline / reproduce

The supplied RAW PDF and a generated processed file were present in the working
tree, but the routing/runtime contract was incomplete:

| Case | Baseline | Expected |
|---|---|---|
| `DHV là trường gì?` | `SCHOOL_INFO` and `thong_tin_truong` already worked | Preserve |
| `Trường thành lập khi nào?` | `OUT_OF_SCOPE`, no category | `SCHOOL_INFO` → `thong_tin_truong` |
| `Website của trường là gì?` | Legacy contact route, only the first provenance URL was usable | Keep compatibility and select the requested official school URL |
| `Web tuyển sinh DHV?` | Legacy contact route, only the first provenance URL was usable | Keep compatibility and select the admissions portal URL |
| `DHV có những cơ sở nào?` | Contact route | Preserve specialized contact route |
| `Đây có phải toàn bộ thông tin về trường không?` | Deterministic `SYSTEM_SCOPE` | Preserve; no retrieval/LLM |

Root causes were missing school-establishment markers in the analyzer and scope
guard, no school-information mapping in the fallback `topic_category`, and
website provenance logic that ignored the PDF's `source_urls` collection.

## Current result

- The school PDF is retained as RAW PDF only and is regenerated to processed
  Markdown by the existing pipeline.
- Processed metadata includes `category: "thong_tin_truong"`, `year: 2026`,
  `status: "verified"`, `verification_status: "verified"`, `source_url` and
  all `source_urls` extracted from the PDF.
- `SCHOOL_INFO` routes to `thong_tin_truong`.
- Website questions retain the compatible `HOI_CO_SO_LIEN_HE` intent while the
  route also permits `thong_tin_truong` provenance. School website and
  admissions portal URLs are selected deterministically from verified metadata.
- Specialized questions continue to use their own categories; the school-info
  document is not used as a replacement for score, tuition, scholarship,
  application, method or supplementary sources.
- `SYSTEM_SCOPE` remains deterministic and returns no sources.
- UI URL hiding remains unchanged: URLs are backend provenance only and are not
  rendered as source cards/URLs in Streamlit.

## Architecture decisions

1. Keep `SCHOOL_INFO` as the general school-information intent; do not create a
   duplicate `HOI_THONG_TIN_TRUONG` implementation.
2. Keep the legacy website/contact intent for compatibility, but add the school
   category as a provenance option for website requests.
3. Resolve website vs admissions portal by deterministic URL-host selection from
   `source_urls`; do not ask the LLM to invent or choose URLs.
4. Keep list/count/score/source boundaries unchanged and use the school PDF only
   for identity, establishment, website/portal and general school context.
